# 本地链式账本节点（Go）

一个零外部依赖、可本地运行的链式账本节点：用本地内存账本模拟账户余额与交易，
在**区块乱序/重复/篡改到达、分叉与链重组、并发提交交易**等情况下，
保证账户状态始终一致、确定且可解释。

## 目录结构

| 包 | 职责 |
| --- | --- |
| `types` | 地址、交易、区块及其 SHA-256 内容哈希；网络区块公告 `Announce` |
| `state` | 账户余额与 nonce；交易校验/执行；深拷贝快照；状态相等性比较 |
| `pool` | 交易池：nonce 顺序与“含池内支出”的余额校验、打包移除、重组后重校验 |
| `chain` | 区块树：区块导入校验、分叉选择、链重组、顶端状态与全量重放核对 |
| `node`  | 并发安全门面：读写锁串行化导入/提交/查询，协调链与交易池 |
| `main.go` | 端到端演示（分叉、重组、交易池拒绝、打包） |

## 数据模型

- `Transaction{From, To, Nonce, Value}`：从 `From` 向 `To` 转移 `Value`。
  `Nonce` 是发送方单调递增序号（首笔为 0），用于确定执行顺序、防止重放。
- `Block{ParentHash, Height, Weight, Txs}`：`ParentHash` 形成哈希链；
  `Weight` 是区块权重（工作量证明的抽象）；`Txs` 在区块内按顺序执行。
- 区块哈希覆盖**全部字段**（父哈希、高度、权重、每笔交易哈希），
  任意内容或顺序被篡改都会改变哈希。

## 区块导入与校验

`Chain.Import`（本地，自算哈希）/ `Chain.ImportAnnounced`（网络，带声明哈希）
按顺序执行以下校验，**任何一步失败都拒绝整块，链状态完全不变**：

| 场景 | 返回哨兵错误 | 含义 |
| --- | --- | --- |
| 重复导入 | `ErrDuplicate` | 该哈希区块已存在 |
| 内容被篡改 | `ErrTampered` | 公告声明哈希 ≠ 接收方重算哈希（仅 `ImportAnnounced`） |
| 父区块缺失 | `ErrParentMissing` | 父哈希未知，通常是乱序提前到达 |
| 高度错乱 | `ErrHeightMismatch` | `Height != parent.Height + 1` |
| 区块内非法交易 | `ErrInvalidTx` | 某笔交易 nonce 不符或余额不足 |
| 创世不合法 | `ErrBadGenesis` | 创世高度非 0 或父哈希非零 |

错误均可用 `errors.Is` 区分；乱序到达的区块**不会**在树中留下半成品节点，
父区块之后到达即可正常补齐（见 `TestImportValidation`）。

校验通过后区块才挂入区块树，随后重算分叉选择。

## 分叉选择规则

主链候选为每个**末端节点**（没有子块的区块）沿父指针回溯到创世块的完整路径，
按以下统一规则比较，结果确定、可复现：

1. **累积权重最大者胜出**：路径上每个区块 `Weight` 之和最大的为主链
   （比较的是“累积工作量”，而不是单纯的区块高度）；
2. **平手按末端哈希字节序决胜**：累积权重相同时，末端哈希字典序较小者胜出。

## 重组语义

当新区块使另一分叉的累积权重反超时，主链切换到该分叉，触发重组（reorg）：

- **不做增量余额补丁**。每个区块节点在导入时就持有“父状态 + 本块交易”
  派生出的**独立深拷贝状态**；分叉之间互不污染。
- 切换顶端等价于：**回到共同祖先后丢弃旧分叉状态，再从共同祖先按顺序
  重放新分叉交易**。
- 因此重组结果与“从创世块直接按新主链顺序完整重放”在数学上完全一致，
  不会出现余额重复计算或丢失、nonce 错乱。
- `Chain.ReplayFromGenesis()` 从创世完整重放；`Chain.VerifyTipState()`
  逐账户比较顶端缓存状态与全量重放状态，作为重组正确性的最终判据
  （所有测试在每次重组后都会断言它为 `true`）。
- 重组发生时 `Node` 会用新的主链顶端状态刷新交易池（`Pool.OnNewTip`）：
  已落账的交易被清除，在新主链上不再合法的交易被剔除，其余交易按新基准重新校验。

## 交易池

- 池中维护 `base`（主链顶端状态副本）与 `proj`（在 base 上顺序叠加池内
  全部交易后的投影状态）。新交易针对 `proj` 校验：
  - nonce 必须等于发送方“链上已用 + 池内待执行”之后的下一个值
    → nonce 有缺口、重复、回退一律拒绝（`state.ErrNonceMismatch`）；
  - 余额校验把池内已有支出计入 → 叠加后余额不足拒绝
    （`state.ErrInsufficientBalance`），而非静默排队；
  - 发送方账户不存在 → `state.ErrSenderMissing`；
  - 同发送方同 nonce 已在池中 → `pool.ErrAlreadyPending`。
- `Pending()` 按 `(发送方地址, nonce)` 确定排序返回可打包交易。
- 交易被打包进区块后，随主链状态刷新自然从池中移除。

## 并发约束

- `Node` 内部一把 `sync.RWMutex`：
  - 区块导入、交易提交、出块打包走**写锁**，彼此互斥；
  - 余额/nonce/主链查询走**读锁**，可彼此并行；
- 因此外部永远观察不到“导入一半 / 重组一半”的中间状态；
  读到的余额与主链要么是切换前、要么是切换后的完整一致状态。
- 底层 `state` / `pool` / `chain` 自身不加锁，约定仅由持锁的 `Node` 访问。
- 并发正确性以 `go test -race ./...` 验证（见 `TestConcurrent`）。

## 本地验证

```bash
go build ./...          # 编译
go vet ./...            # 静态检查
go run .                # 端到端演示：分叉/重组/交易池/打包
go test ./... -v        # 详细单测日志（按业务分组打印用例与结果）
go test ./... -race     # 竞态检测
```

## 测试覆盖

- `chain.TestReorg`：高权分支胜出、平手哈希决胜、二次重组来回切换；
  每次断言重组后余额/nonce 与全量重放一致。
- `chain.TestImportValidation`：父缺失（乱序）、高度错乱、内容篡改、
  重复导入、区块内非法交易、乱序补齐。
- `pool.TestPool`：nonce 连续性、含池内支出的余额校验、确定性排序、
  移除重建、`OnNewTip` 重组后清理已落账交易。
- `state.TestState`：转账与 nonce 推进、三类可区分错误、克隆隔离与守恒。
- `node.TestPoolValidation` / `TestPackAndReorgPool`：入池拒绝原因、
  打包移除、重组后交易可重新接纳。
- `node.TestConcurrent`：8 个发送方各 50 笔并发提交 + 持续读 +
  并发导入空块，`-race` 下无数据竞争、总账守恒、状态与重放一致。
